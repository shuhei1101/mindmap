# コマンド

スキルが呼ぶスクリプトのコマンドの一覧。
どれも `{仮想環境の Python} {スキルのフォルダ}/scripts/mindmap.py` の後ろにコマンド名を続けて実行する（`{スキルのフォルダ}` はスキル mindmap のフォルダ）。
`{仮想環境の Python}` は `check-env` が返す `python_path`（スキル専用の仮想環境の Python）で、`check-env` だけはシステムの `python3` で実行する。

- 標準出力に JSON を 1 個出す（UTF-8、日本語はエスケープしない）
- エラーは標準エラーに `エラー: {内容}` の行で出す。スキーマに合わないときは、続けて合わない箇所ごとに `{ファイル名}: {キーのパス}: {理由}` の行を出す（キーのパスは `items[0].status` の形）
- 終了コードは `0` が正常、`1` が実行時のエラー、`2` が引数の誤り
- `--workspace` はワークスペース（`mindmap.yaml` があるフォルダ）のパス。`check-env` 以外は必ず渡す
- 書き込むコマンド（`init`・`add`・`update`・`adopt`）は、書き込む前にワークスペースの全ての YAML をスキーマと突き合わせ、合わなければ何も書き換えない。同じワークスペースへ同時に書き込まない（ロックは持たない）

## 一覧

| 名前 | コマンド | 説明 |
| --- | --- | --- |
| [依存を確かめる](#依存を確かめる) | `mindmap.py check-env` | スキル専用の仮想環境の Python と PyYAML・jsonschema の版を確かめる |
| [ワークスペースを作る](#ワークスペースを作る) | `mindmap.py init` | 設定を受け取って空のワークスペースを作る |
| [項目を足す](#項目を足す) | `mindmap.py add` | 1 項目を足す |
| [項目を直す](#項目を直す) | `mindmap.py update` | 1 項目のキーを置き換える |
| [採用する案を切り替える](#採用する案を切り替える) | `mindmap.py adopt` | 検討事項の採用する案を 1 つに切り替える |
| [再開時の状況を読む](#再開時の状況を読む) | `mindmap.py status` | 要見直し・進行中・再開可能・決定待ち・次の候補をまとめて返す |

| [ワークスペースを点検する](#ワークスペースを点検する) | `mindmap.py check` | スキーマ違反・参照切れ・本文のずれを洗い出す |
| [プレビューを書き出す](#プレビューを書き出す) | `mindmap.py build` | 記録を埋め込んだ `preview.html` を書き出す |

## 依存を確かめる

スキル専用の仮想環境に、下限以上の Python・PyYAML・jsonschema がそろっているかを確かめ、ほかのコマンドを起動する Python と、足りないときにそろえるコマンドを返す。
何も書き込まず、通信もしない。

### 使い方

```bash
python3 {スキルのフォルダ}/scripts/mindmap.py check-env [--venv {フォルダ}]
```

### 引数

| 引数 | 必須 | 説明 |
| --- | --- | --- |
| `--venv` | - | 確かめる仮想環境のフォルダ。省略すると `~/.mindmap/venv`（Windows は `%USERPROFILE%\.mindmap\venv`） |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `venv` | str | 確かめた仮想環境のフォルダ |
| `venv_ok` | bool | 仮想環境の Python があるか |
| `python_path` | str | ほかのコマンドを起動する Python |
| `python` | str \| null | 仮想環境の Python の版。仮想環境が無ければ `null` |
| `python_ok` | bool | 仮想環境の Python の版が 3.12 以上か |
| `base_python` | str | 仮想環境を作る Python（`check-env` を動かしている Python）のパス |
| `base_python_version` | str | 仮想環境を作る Python の版 |
| `base_python_ok` | bool | 仮想環境を作る Python の版が 3.12 以上か |
| `packages[].name` | str | 確かめたライブラリ（`PyYAML`・`jsonschema`） |
| `packages[].required` | str | 版の下限 |
| `packages[].installed` | str \| null | 仮想環境に入っている版。入っていなければ `null` |
| `packages[].ok` | bool | 下限以上が入っているか |
| `install` | str \| null | 仮想環境とライブラリをそろえるコマンド（仮想環境が無ければ作る、Python が古ければ作り直す）。全てそろっていれば `null`。作る・作り直すときに `base_python_ok` が `false` なら `null` |

### 終了コード

| コード | 意味 |
| --- | --- |
| `0` | 仮想環境があり、その Python と両方のライブラリが下限以上 |
| `1` | 仮想環境が無いか、その Python が下限より古いか、ライブラリが足りない（出力は同じ形） |

## ワークスペースを作る

標準入力で渡した設定を持つ `mindmap.yaml` と、空の種類ごとの YAML・`docs/`・`handoff/` を作る。
既にワークスペースがあるフォルダには作らない。

### 使い方

```bash
{仮想環境の Python} {スキルのフォルダ}/scripts/mindmap.py init --workspace {フォルダ} < {設定の JSON のファイル}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `--workspace` | 必須 | 作るワークスペースのフォルダ。`mindmap.yaml` がまだ無いフォルダで、フォルダが無ければ作る | - |
| 標準入力 | 必須 | 設定の JSON のオブジェクト（`field`・`target_label`・`phases`・`targets`・`categories`・`goal`・`links`）。キーは [ワークスペースの書式](./ワークスペースの書式.md#設定) | `{"field": "システム開発", "target_label": "システム", "phases": ["目的", "要件"], ...}` |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `workspace` | str | 作ったワークスペースの絶対パス |
| `files` | list[str] | 作ったファイルとフォルダ（ワークスペースからの相対パス） |

### 終了コード

| コード | 意味 |
| --- | --- |
| `0` | 作れた |
| `1` | `mindmap.yaml` が既にある・設定がスキーマに合わない・書き込めなかった（どれも `mindmap.yaml` を残さない） |

## 項目を足す

標準入力で渡した中身に ID・作成日時・更新日時を付けて、種類の YAML に 1 項目足す。
ID は種類の頭の文字 + その種類の連番の最大 + 1 で振る。
参照先の ID があるかは確かめない（[ワークスペースを点検する](#ワークスペースを点検する)が確かめる）。

### 使い方

```bash
{仮想環境の Python} {スキルのフォルダ}/scripts/mindmap.py add {種類} --workspace {フォルダ} < {項目の JSON のファイル}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `種類` | 必須 | 足す項目の種類（位置引数）。書き込む YAML と ID の頭の文字が決まる（`decision` → `decisions.yaml`・`D` / `task` → `tasks.yaml`・`T` / `research` → `research.yaml`・`R` / `doc` → `docs.yaml`・`A` / `term` → `terms.yaml`・`G` / `note` → `notes.yaml`・`N` / `log` → `logs.yaml`・`L`） | `decision` |
| `--workspace` | 必須 | ワークスペースのフォルダ | - |
| 標準入力 | 必須 | 項目の中身の JSON のオブジェクト。キーは [ワークスペースの書式](./ワークスペースの書式.md)のその種類のもの。`id`・`created`・`updated`・`body` は渡さない | `{"title": "YAML のキーをどう分けるか", "status": "未決定", "weight": "大"}` |
| 標準入力の `body_markdown` | 任意 | 本文の Markdown。YAML には残らず `docs/{ID}.md` に書かれ、項目の `body` が `{ID}.md` になる。調査・資料・検討事項・会話ログだけが持てる（資料は必須） | `"## 経緯\n\n..."` |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `id` | str | 振った ID |
| `file` | str | 書いた YAML（ワークスペースからの相対パス） |
| `body` | str \| null | 書いた本文の Markdown（ワークスペースからの相対パス）。本文が無ければ `null` |

### 終了コード

| コード | 意味 |
| --- | --- |
| `0` | 足せた |
| `1` | ワークスペースが無い・足した後の YAML がスキーマに合わない・書き込めなかった（どのファイルも書き換えない） |

## 項目を直す

ID で指した 1 項目のキーを、標準入力で渡した値に置き換えて、更新日時を変える。

### 使い方

```bash
{仮想環境の Python} {スキルのフォルダ}/scripts/mindmap.py update {ID} --workspace {フォルダ} < {変えるキーの JSON のファイル}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `ID` | 必須 | 直す項目の ID（位置引数）。頭の文字で書き換える YAML が決まる | `D-2` |
| `--workspace` | 必須 | ワークスペースのフォルダ | - |
| 標準入力 | 必須 | 置き換えるキーと値の JSON のオブジェクト。渡したキーだけを値ごと置き換え（配列・オブジェクトも丸ごと）、値が `null` のキーは消す。渡さないキーはそのまま。`id`・`created`・`updated`・`body` は渡さない | `{"answer": "種類ごとに分ける", "status": "決定済み", "weight": null}` |
| 標準入力の `body_markdown` | 任意 | 本文の Markdown。`docs/{ID}.md` をこの内容で置き換える。調査・資料・検討事項・会話ログだけが持てる | - |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `id` | str | 直した項目の ID |
| `file` | str | 書き換えた YAML（ワークスペースからの相対パス） |
| `changed` | list[str] | 値が変わった・消えたキーの名前（`updated` は含めない） |

### 終了コード

| コード | 意味 |
| --- | --- |
| `0` | 直せた |
| `1` | ワークスペースが無い・ID の項目が無い・直した後の YAML がスキーマに合わない・書き込めなかった（どのファイルも書き換えない） |

## 採用する案を切り替える

検討事項の案のうち、指定した記号の案だけを採用にし、ほかの案の採用を外す。
状態と答えは変えない。
影響を洗い出さない（[影響を洗い出す](#影響を洗い出す)が持つ）。

### 使い方

```bash
{仮想環境の Python} {スキルのフォルダ}/scripts/mindmap.py adopt {ID} {記号} --workspace {フォルダ}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `ID` | 必須 | 検討事項の ID（位置引数の 1 つめ）。`D-` で始まる | `D-1` |
| `記号` | 必須 | 採用する案の記号（位置引数の 2 つめ。`options[].key`） | `B` |
| `--workspace` | 必須 | ワークスペースのフォルダ | - |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `id` | str | 検討事項の ID |
| `adopted` | str | 採用した案の記号 |
| `previous` | str \| null | それまで採用していた案の記号。無ければ `null` |

### 終了コード

| コード | 意味 |
| --- | --- |
| `0` | 切り替えた（既にその案が採用のときも含む） |
| `1` | ワークスペースが無い・検討事項が無い・渡した記号の案が無い（標準エラーに、その検討事項が持つ案の記号の一覧）・切り替えた後の YAML がスキーマに合わない・書き込めなかった（どのファイルも書き換えない） |

## 再開時の状況を読む

話し合いを再開するときに読む状況をまとめて返す。
読むだけで、ファイルを書き換えない。

### 使い方

```bash
{仮想環境の Python} {スキルのフォルダ}/scripts/mindmap.py status --workspace {フォルダ}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `--workspace` | 必須 | ワークスペースのフォルダ | - |

### 出力

決着は、検討事項が `決定済み`・`対象外`・`取り下げ`、タスクが `完了`・`中止`。
存在しない ID は未完了として扱う。
各一覧は ID の種類（D → T）、連番の小さい順に並ぶ（`next` を除く）。

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `needs_review[]` | list[{id, title}] | 状態が `要見直し` の検討事項 |
| `in_progress[]` | list[{id, title}] | 状態が `進行中` のタスク |
| `resumable[]` | list[{id, title}] | 状態が `保留` で、`depends_on` が 1 つ以上あり全て決着した検討事項・タスク |
| `waiting[]` | list[{id, title, waiting_for}] | 状態が `保留` で、`depends_on` に未完了が残る検討事項・タスク。`waiting_for` は未完了の `depends_on` の ID |
| `on_hold[]` | list[{id, title, reason}] | 状態が `保留` で `depends_on` を持たない検討事項・タスク |
| `next[]` | list[{id, title, phase, weight, followers}] | [次の候補を読む](#次の候補を読む)の先頭 3 件 |

### 終了コード

| コード | 意味 |
| --- | --- |
| `0` | まとめられた |
| `1` | ワークスペースが無い |

## 次の候補を読む

状態が `未決定` で、`depends_on` の検討事項が全て決着しているものを、決める順に並べて返す（存在しない ID を指すものは候補にしない）。
読むだけで、ファイルを書き換えない。

### 使い方

```bash
{仮想環境の Python} {スキルのフォルダ}/scripts/mindmap.py next --workspace {フォルダ} [--limit {件数}]
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `--workspace` | 必須 | ワークスペースのフォルダ | - |
| `--limit` | 任意 | 返す候補の件数の上限（1 以上）。渡さなければ全件 | `--limit 3` |

### 出力

並びは、フェーズの並び（設定の `phases` の順。フェーズが無い・設定に無いものは最後）→ 影響度（大 → 中 → 小 → 無し）→ 後続の件数の多い順 → ID の連番の小さい順。

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `candidates[].id` | str | 検討事項の ID |
| `candidates[].title` | str | タイトル |
| `candidates[].phase` | str \| null | フェーズ |
| `candidates[].weight` | `大` \| `中` \| `小` \| null | 影響度 |
| `candidates[].followers` | int | 後続の件数（[影響を洗い出す](#影響を洗い出す)と同じたどり方で得た項目のうち、未完了のものの数） |

### 終了コード

| コード | 意味 |
| --- | --- |
| `0` | 並べられた（候補が 0 件のときも含む） |
| `1` | ワークスペースが無い |

## 影響を洗い出す

指定した項目から、`depends_on`・`parent`・`for` を逆向きにたどって影響を受ける項目を返す。
項目 X に対し、`depends_on` か `parent` に X を持つ項目と、`for` に X を持つタスクを影響を受ける項目にし、得た項目から同じようにたどる。
`related`・`sources` はたどらない。
状態では絞らず、決定済み・完了も含めて出す。
読むだけで、ファイルを書き換えない。

### 使い方

```bash
{仮想環境の Python} {スキルのフォルダ}/scripts/mindmap.py impact {ID} --workspace {フォルダ}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `ID` | 必須 | 起点の項目の ID（位置引数） | `D-1` |
| `--workspace` | 必須 | ワークスペースのフォルダ | - |

### 出力

一度出た項目は、起点も含めて 2 度出ない。

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `id` | str | 起点の項目の ID |
| `affected[].id` | str | 影響を受ける項目の ID。起点に近い順、同じ距離は ID の順 |
| `affected[].title` | str | タイトル |
| `affected[].status` | str | 状態 |
| `affected[].via` | list[str] | 起点からたどった経路（起点とこの項目の間にある項目の ID。直接なら空）。最短の 1 本 |
| `affected[].key` | `depends_on` \| `parent` \| `for` | 直前の項目とこの項目をつなぐキー |

### 終了コード

| コード | 意味 |
| --- | --- |
| `0` | 洗い出せた（影響を受ける項目が 0 件のときも含む） |
| `1` | ワークスペースが無い・ID の項目が無い |

## 項目を探す

文字・種類・状態・タグ・対象・カテゴリー・フェーズ・属性の条件に合う項目を返す。
渡した条件の全てに合う項目を返し、条件を 1 つも渡さなければ全ての項目を返す。
読むだけで、ファイルを書き換えない。

### 使い方

```bash
{仮想環境の Python} {スキルのフォルダ}/scripts/mindmap.py find --workspace {フォルダ} [--text {文字}] [--kind {種類}] [--status {状態}] [--tag {タグ}] [--target {対象}] [--category {カテゴリー}] [--phase {フェーズ}] [--attr {名前=値}]
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `--workspace` | 必須 | ワークスペースのフォルダ | - |
| `--text` | 任意 | 項目の文字の欄（入れ子の `options[]` なども含む、YAML の全ての文字列の値）のどれかに含まれる文字。英字の大小を区別しない。`docs/` の本文は探さない | `--text スキーマ` |
| `--kind` | 任意 | 種類（`decision`・`task`・`research`・`doc`・`term`・`note`・`log`）。渡さなければ全ての種類 | `--kind decision` |
| `--status` | 任意 | 状態が一致する項目 | `--status 未決定` |
| `--tag` | 任意 | タグに持つ項目 | `--tag 脱線` |
| `--target` | 任意 | 対象が一致する項目 | - |
| `--category` | 任意 | カテゴリーが一致する項目 | - |
| `--phase` | 任意 | フェーズが一致する項目 | `--phase 要件` |
| `--attr` | 任意 | `名前=値` の形で、属性が一致する項目。繰り返し渡せる（全てに合うもの）。`名前` だけならその属性を持つ項目 | `--attr 担当=自分` |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |

## ワークスペースを点検する

スキーマに合わない箇所・参照切れ・YAML と `docs/` の Markdown のずれを全て洗い出す。
見つけた問題は直さない。

- 参照切れは、`depends_on`・`parent`・`for`・`related`・`sources` と設定の `goal.deliverables[].doc` が、存在しない ID や、キーが決めた種類でない ID（`parent` が `D-` 以外 など）を指しているもの
- 本文のずれは、`body` が指す `docs/` のファイルが無いもの（`missing_body`）と、どの項目の `body` からも指されない `docs/` の Markdown（`orphan_body`）

### 使い方

```bash
{仮想環境の Python} {スキルのフォルダ}/scripts/mindmap.py check --workspace {フォルダ}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `--workspace` | 必須 | ワークスペースのフォルダ | - |

### 出力

問題があるときも点検そのものは正常に終えているので、標準出力に同じ形の JSON を出し、終了コードだけを `1` にする。
`problems` はファイル名の順、同じファイルの中は項目の並びの順に並ぶ。

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `ok` | bool | 問題が 1 つも無いか |
| `problems[].kind` | `schema` \| `duplicate_id` \| `broken_ref` \| `missing_body` \| `orphan_body` | 問題の種類（スキーマに合わない・ID の重複・参照切れ・指す本文が無い・どの項目からも指されない本文） |
| `problems[].file` | str | 問題のあるファイル（ワークスペースからの相対パス） |
| `problems[].id` | str \| null | 問題のある項目の ID（`orphan_body` と、項目を特定できない `schema` は `null`） |
| `problems[].key` | str \| null | 問題のあるキーのパス（`items[0].status`・`depends_on` など） |
| `problems[].detail` | str | 中身（参照先の ID・スキーマの理由など） |

### 終了コード

| コード | 意味 |
| --- | --- |
| `0` | 問題が無い |
| `1` | 問題がある、またはワークスペースが無い（このとき標準出力には何も出さない） |

## プレビューを書き出す

ワークスペースの全ての YAML と本文を 1 つの JSON にまとめ、プレビューの画面の雛形に埋め込んだ 1 ファイル `preview.html` を書き出す。
サーバーは立てず、ブラウザも開かない。
描画のライブラリは、開いたブラウザが CDN から読む。
YAML がスキーマに合わないときは書き出さず、前の `preview.html` を残す。

### 使い方

```bash
{仮想環境の Python} {スキルのフォルダ}/scripts/mindmap.py build --workspace {フォルダ}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `--workspace` | 必須 | ワークスペースのフォルダ | - |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `path` | str | 書き出した `preview.html` の絶対パス |

`preview.html` には、雛形の `<script type="application/json" id="mindmap-data"></script>` の中身として、次のデータが入る。
画面はこの要素の中身を `JSON.parse` して読む。

| キー | 型 | 説明 |
| --- | --- | --- |
| `settings` | dict | `mindmap.yaml` の中身 |
| `decisions` / `tasks` / `research` / `docs` / `terms` / `notes` / `logs` | list[dict] | 種類ごとの YAML の `items` の中身（キー名はファイル名から `.yaml` を落としたもの） |
| `bodies` | dict[str, str] | `docs/` のファイル名 → 本文の Markdown（項目の `body` が指すものだけ） |
| `built_at` | str | 書き出した日時（UTC のタイムゾーン付き ISO 8601） |

### 終了コード

| コード | 意味 |
| --- | --- |
| `0` | 書き出せた |
| `1` | ワークスペースが無い・YAML がスキーマに合わないか YAML として読めない・書き込めなかった（前の `preview.html` を残す） |
