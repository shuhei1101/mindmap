# コマンド

スキルが呼ぶスクリプトのコマンドの一覧。
どれも `python3 {スキルのフォルダ}/scripts/mindmap.py` の後ろにコマンド名を続けて実行する（`{スキルのフォルダ}` はプラグインの `skills/mindmap/` のフォルダ）。
`check-env` 以外のコマンドは、起動した Python が下限以上の Python・PyYAML・jsonschema を持っていなければ、スキル専用の仮想環境の Python で 1 回だけ起動し直す。
起動し直したときも、引数・標準入力・標準出力・標準エラー・終了コード・作業フォルダはそのまま引き継ぐ。
仮想環境が無いか、仮想環境にも依存が足りないときは、標準エラーに `エラー: {内容}` と `check-env` を実行する促しの行を出し、標準出力には何も出さず、終了コード `1` で終わる。

- 標準出力に JSON を 1 個出す（UTF-8、日本語はエスケープしない）
- エラーは標準エラーに `エラー: {内容}` の行で出す。スキーマに合わないときは、続けて合わない箇所ごとに `{ファイル名}: {キーのパス}: {理由}` の行を出す（キーのパスは `items[0].status` の形）
- `add`・`update`・`adopt`・`build` は、合わない箇所に前の版の形式（資料の `done`・設定の `summary` が無い）があるとき、最後に `ヒント: 前の版の形式の記録は /mindstella:upgrade で今の形式に移せます` の行を続ける。前の版の形式の記録は [ワークスペースを移し替える](./スキル.md#ワークスペースを移し替える)スキルが [記録の形式を移す](#記録の形式を移す)を呼んで移す
- 終了コードは `0` が正常、`1` が実行時のエラー、`2` が引数の誤り
- `--workspace` はワークスペース（`mindmap.yaml` があるフォルダ）のパス。`check-env` 以外は必ず渡す
- 書き込むコマンド（`init`・`add`・`update`・`adopt`・`migrate`・`clear-release`）は、書き込む前にワークスペースの全ての YAML をスキーマと突き合わせ（`clear-release` を除く）、合わなければ何も書き換えない。`migrate` は、手順を当てるときと `--set` では突き合わせず、`--record` で版を書く前に突き合わせる。同じワークスペースへ同時に書き込まない（ロックは持たない）

## 依存を確かめる

スキル専用の仮想環境に、下限以上の Python・PyYAML・jsonschema がそろっているかを確かめ、ほかのコマンドの起動し直し先の Python と、足りないときにそろえるコマンドを返す。
何も書き込まず、通信もしない。

### 使い方

```bash
python3 {スキルのフォルダ}/scripts/mindmap.py check-env [--venv {フォルダ}]
```

### 引数

| 引数 | 必須 | 説明 |
| --- | --- | --- |
| `--venv` | - | 確かめる仮想環境のフォルダ。省略すると `~/.mindmap/venv`（Windows は `%USERPROFILE%\.mindmap\venv`） |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `venv` | str | 確かめた仮想環境のフォルダ |
| `venv_ok` | bool | 仮想環境の Python があるか |
| `python_path` | str | ほかのコマンドの起動し直し先の Python |
| `python` | str \| null | 仮想環境の Python の版。仮想環境が無ければ `null` |
| `python_ok` | bool | 仮想環境の Python の版が 3.12 以上か |
| `base_python` | str | 仮想環境を作る Python（`check-env` を動かしている Python）のパス |
| `base_python_version` | str | 仮想環境を作る Python の版 |
| `base_python_ok` | bool | 仮想環境を作る Python の版が 3.12 以上か |
| `packages[].name` | str | 確かめたライブラリ（`PyYAML`・`jsonschema`） |
| `packages[].required` | str | 版の下限 |
| `packages[].installed` | str \| null | 仮想環境に入っている版。入っていなければ `null` |
| `packages[].ok` | bool | 下限以上が入っているか |
| `install` | str \| null | 仮想環境とライブラリをそろえるコマンド（仮想環境が無ければ作る、Python が古ければ作り直す）。全てそろっていれば `null`。作る・作り直すときに `base_python_ok` が `false` なら `null` |

### 終了コード

| コード | 意味 |
| --- | --- |
| `0` | 仮想環境があり、その Python と両方のライブラリが下限以上 |
| `1` | 仮想環境が無いか、その Python が下限より古いか、ライブラリが足りない（出力は同じ形） |

## ワークスペースを作る

標準入力か `--json` で渡した設定を持つ `mindmap.yaml` と、空の種類ごとの YAML・`docs/`・`release/`・プラグインの版を書いた `mindstella-version.ini` を作る。
既にワークスペースがあるフォルダには作らない。

### 使い方

```bash
python3 {スキルのフォルダ}/scripts/mindmap.py init --workspace {フォルダ} < {設定の JSON のファイル}
python3 {スキルのフォルダ}/scripts/mindmap.py init --workspace {フォルダ} --json '{設定の JSON}'
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `--workspace` | 必須 | 作るワークスペースのフォルダ。`mindmap.yaml` がまだ無いフォルダで、フォルダが無ければ作る | - |
| 標準入力 | 任意 | `--json` を渡さないときに読む。設定の JSON のオブジェクト（`summary`・`field`・`target_label`・`phases`・`targets`・`categories`・`goal`・`links`）。キーは [ワークスペースの書式](./ワークスペースの書式.md#設定) | `{"summary": "家計簿アプリの要件を決める", "field": "システム開発", "target_label": "システム", "phases": ["目的", "要件"], ...}` |
| `--json` | 任意 | 標準入力と同じ設定の JSON を 1 つの引数で渡す。渡したときは標準入力を読まない。シェルの引用符（`'`）で囲む。値の中の `'` は `'\''` と書く | `--json '{"summary": "家計簿アプリの要件を決める", "field": "システム開発", ...}'` |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `workspace` | str | 作ったワークスペースの絶対パス |
| `files` | list[str] | 作ったファイルとフォルダ（ワークスペースからの相対パス） |

### 終了コード

| コード | 意味 |
| --- | --- |
| `0` | 作れた |
| `1` | `mindmap.yaml` が既にある・設定がスキーマに合わない・書き込めなかった（どれも `mindmap.yaml` を残さない） |

## 項目を足す

標準入力か `--json` で渡した中身に ID・作成日時・更新日時を付けて、種類の YAML に 1 項目足す。
ID は種類の頭の文字 + その種類の連番の最大 + 1 で振る。
参照先の ID があるかは確かめない（[ワークスペースを点検する](#ワークスペースを点検する)が確かめる）。

### 使い方

```bash
python3 {スキルのフォルダ}/scripts/mindmap.py add {種類} --workspace {フォルダ} < {項目の JSON のファイル}
python3 {スキルのフォルダ}/scripts/mindmap.py add {種類} --workspace {フォルダ} --json '{項目の JSON}'
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `種類` | 必須 | 足す項目の種類（位置引数）。書き込む YAML と ID の頭の文字が決まる（`decision` → `decisions.yaml`・`D` / `task` → `tasks.yaml`・`T` / `research` → `research.yaml`・`R` / `doc` → `docs.yaml`・`A` / `term` → `terms.yaml`・`G` / `note` → `notes.yaml`・`N` / `log` → `logs.yaml`・`L`） | `decision` |
| `--workspace` | 必須 | ワークスペースのフォルダ | - |
| 標準入力 | 任意 | `--json` を渡さないときに読む。項目の中身の JSON のオブジェクト。キーは [ワークスペースの書式](./ワークスペースの書式.md)のその種類のもの。`id`・`created`・`updated`・`body` は渡さない | `{"title": "YAML のキーをどう分けるか", "status": "未決定", "weight": "大"}` |
| `--json` | 任意 | 標準入力と同じ項目の中身の JSON を 1 つの引数で渡す。渡したときは標準入力を読まない。シェルの引用符（`'`）で囲む。値の中の `'` は `'\''` と書く | `--json '{"title": "YAML のキーをどう分けるか", "status": "未決定"}'` |
| 標準入力・`--json` の `body_markdown` | 任意 | 本文の Markdown。YAML には残らず `docs/{ID}.md` に書かれ、項目の `body` が `{ID}.md` になる。調査・資料・検討事項・会話ログだけが持てる（資料は必須） | `"## 経緯\n\n..."` |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `id` | str | 振った ID |
| `file` | str | 書いた YAML（ワークスペースからの相対パス） |
| `body` | str \| null | 書いた本文の Markdown（ワークスペースからの相対パス）。本文が無ければ `null` |

### 終了コード

| コード | 意味 |
| --- | --- |
| `0` | 足せた |
| `1` | ワークスペースが無い・足した後の YAML がスキーマに合わない・書き込めなかった（どのファイルも書き換えない） |

## 項目を直す

ID で指した 1 項目のキーを、標準入力か `--json` で渡した値に置き換えて、更新日時を変える。

### 使い方

```bash
python3 {スキルのフォルダ}/scripts/mindmap.py update {ID} --workspace {フォルダ} < {変えるキーの JSON のファイル}
python3 {スキルのフォルダ}/scripts/mindmap.py update {ID} --workspace {フォルダ} --json '{変えるキーの JSON}'
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `ID` | 必須 | 直す項目の ID（位置引数）。頭の文字で書き換える YAML が決まる | `D-2` |
| `--workspace` | 必須 | ワークスペースのフォルダ | - |
| 標準入力 | 任意 | `--json` を渡さないときに読む。置き換えるキーと値の JSON のオブジェクト。渡したキーだけを値ごと置き換え（配列・オブジェクトも丸ごと）、値が `null` のキーは消す。渡さないキーはそのまま。`id`・`created`・`updated`・`body` は渡さない | `{"answer": "種類ごとに分ける", "status": "決定済み", "weight": null}` |
| `--json` | 任意 | 標準入力と同じ置き換えるキーの JSON を 1 つの引数で渡す。渡したときは標準入力を読まない。シェルの引用符（`'`）で囲む。値の中の `'` は `'\''` と書く | `--json '{"status": "決定済み"}'` |
| 標準入力・`--json` の `body_markdown` | 任意 | 本文の Markdown。`docs/{ID}.md` をこの内容で置き換える。調査・資料・検討事項・会話ログだけが持てる | - |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `id` | str | 直した項目の ID |
| `file` | str | 書き換えた YAML（ワークスペースからの相対パス） |
| `changed` | list[str] | 値が変わった・消えたキーの名前（`updated` は含めない） |

### 終了コード

| コード | 意味 |
| --- | --- |
| `0` | 直せた |
| `1` | ワークスペースが無い・ID の項目が無い・直した後の YAML がスキーマに合わない・書き込めなかった（どのファイルも書き換えない） |

## 採用する案を切り替える

検討事項の案のうち、指定した記号の案だけを採用にし、ほかの案の採用を外す。
状態と答えは変えない。
影響を洗い出さない（[影響を洗い出す](#影響を洗い出す)が持つ）。

### 使い方

```bash
python3 {スキルのフォルダ}/scripts/mindmap.py adopt {ID} {記号} --workspace {フォルダ}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `ID` | 必須 | 検討事項の ID（位置引数の 1 つめ）。`D-` で始まる | `D-1` |
| `記号` | 必須 | 採用する案の記号（位置引数の 2 つめ。`options[].key`） | `B` |
| `--workspace` | 必須 | ワークスペースのフォルダ | - |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `id` | str | 検討事項の ID |
| `adopted` | str | 採用した案の記号 |
| `previous` | str \| null | それまで採用していた案の記号。無ければ `null` |

### 終了コード

| コード | 意味 |
| --- | --- |
| `0` | 切り替えた（既にその案が採用のときも含む） |
| `1` | ワークスペースが無い・検討事項が無い・渡した記号の案が無い（標準エラーに、その検討事項が持つ案の記号の一覧）・切り替えた後の YAML がスキーマに合わない・書き込めなかった（どのファイルも書き換えない） |

## 再開時の状況を読む

話し合いを再開するときに読む状況をまとめて返す。
読むだけで、ファイルを書き換えない。

### 使い方

```bash
python3 {スキルのフォルダ}/scripts/mindmap.py status --workspace {フォルダ}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `--workspace` | 必須 | ワークスペースのフォルダ | - |

### 出力

決着は、検討事項が `決定済み`・`対象外`・`取り下げ`、タスクが `完了`・`中止`。
存在しない ID は未完了として扱う。
各一覧は ID の種類（D → T）、連番の小さい順に並ぶ（`next` を除く）。

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `needs_review[]` | list[{id, title}] | 状態が `要見直し` の検討事項 |
| `in_progress[]` | list[{id, title}] | 状態が `進行中` のタスク |
| `resumable[]` | list[{id, title}] | 状態が `保留` で、`depends_on` が 1 つ以上あり全て決着した検討事項・タスク |
| `waiting[]` | list[{id, title, waiting_for}] | 状態が `保留` で、`depends_on` に未完了が残る検討事項・タスク。`waiting_for` は未完了の `depends_on` の ID |
| `on_hold[]` | list[{id, title, reason}] | 状態が `保留` で `depends_on` を持たない検討事項・タスク |
| `next[]` | list[{id, title, phase, weight, followers}] | [次の候補を読む](#次の候補を読む)の先頭 3 件 |

### 終了コード

| コード | 意味 |
| --- | --- |
| `0` | まとめられた |
| `1` | ワークスペースが無い |

## 次の候補を読む

状態が `未決定` で、`depends_on` の検討事項が全て決着しているものを、決める順に並べて返す（存在しない ID を指すものは候補にしない）。
読むだけで、ファイルを書き換えない。

### 使い方

```bash
python3 {スキルのフォルダ}/scripts/mindmap.py next --workspace {フォルダ} [--limit {件数}]
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `--workspace` | 必須 | ワークスペースのフォルダ | - |
| `--limit` | 任意 | 返す候補の件数の上限（1 以上）。渡さなければ全件 | `--limit 3` |

### 出力

並びは、フェーズの並び（設定の `phases` の順。フェーズが無い・設定に無いものは最後）→ 影響度（大 → 中 → 小 → 無し）→ 後続の件数の多い順 → ID の連番の小さい順。

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `candidates[].id` | str | 検討事項の ID |
| `candidates[].title` | str | タイトル |
| `candidates[].phase` | str \| null | フェーズ |
| `candidates[].weight` | `大` \| `中` \| `小` \| null | 影響度 |
| `candidates[].followers` | int | 後続の件数（[影響を洗い出す](#影響を洗い出す)と同じたどり方で得た項目のうち、未完了のものの数） |

### 終了コード

| コード | 意味 |
| --- | --- |
| `0` | 並べられた（候補が 0 件のときも含む） |
| `1` | ワークスペースが無い |

## 影響を洗い出す

指定した項目から、`depends_on`・`parent`・`for` を逆向きにたどって影響を受ける項目を返す。
項目 X に対し、`depends_on` か `parent` に X を持つ項目と、`for` に X を持つタスクを影響を受ける項目にし、得た項目から同じようにたどる。
`related`・`sources` はたどらない。
状態では絞らず、決定済み・完了も含めて出す。
読むだけで、ファイルを書き換えない。

### 使い方

```bash
python3 {スキルのフォルダ}/scripts/mindmap.py impact {ID} --workspace {フォルダ}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `ID` | 必須 | 起点の項目の ID（位置引数） | `D-1` |
| `--workspace` | 必須 | ワークスペースのフォルダ | - |

### 出力

一度出た項目は、起点も含めて 2 度出ない。

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `id` | str | 起点の項目の ID |
| `affected[].id` | str | 影響を受ける項目の ID。起点に近い順、同じ距離は ID の順 |
| `affected[].title` | str | タイトル |
| `affected[].status` | str | 状態 |
| `affected[].via` | list[str] | 起点からたどった経路（起点とこの項目の間にある項目の ID。直接なら空）。最短の 1 本 |
| `affected[].key` | `depends_on` \| `parent` \| `for` | 直前の項目とこの項目をつなぐキー |

### 終了コード

| コード | 意味 |
| --- | --- |
| `0` | 洗い出せた（影響を受ける項目が 0 件のときも含む） |
| `1` | ワークスペースが無い・ID の項目が無い |

## ワークスペースを点検する

- 参照切れは、`depends_on`・`parent`・`for`・`related`・`sources` と設定の `goal.deliverables[].doc` が、存在しない ID や、キーが決めた種類でない ID（`parent` が `D-` 以外 など）を指しているもの

| --- | --- | --- | --- |
| `--workspace` | 必須 | ワークスペースのフォルダ | - |

| フィールド | 型 | 説明 |

## 配る書き出しを作る

ワークスペースの全ての YAML と本文を、画面と描画のライブラリ（marked・DOMPurify・elkjs・mermaid）まで中に持つ、見るだけの 1 枚の HTML にして、指定したパスへ書き出す。
ワークスペースもサーバーもネットも持たない人へ配るために使う。
描画のライブラリの配布ファイルとライセンスの本文は、書き出すときに jsDelivr から取る。
取った配布ファイルは雛形の `integrity` と突き合わせ、合わなければ書き出さない。
1 回の要求で、接続と 1 回の読み取りをそれぞれ 30 秒まで待ち、取り直さない。
書き出した HTML は外のファイルも URL も指さず、開いても通信しない。
ワークスペースへ書き込む操作は画面に出ない。
サーバーは立てず、ブラウザも開かず、`preview.html` は書き換えない。
YAML がスキーマに合わないときと、jsDelivr から取れないときは書き出さず、前の `--out` のファイルを残す。

### 使い方

```bash
python3 {スキルのフォルダ}/scripts/mindmap.py export --workspace {フォルダ} --out {パス}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `--workspace` | 必須 | ワークスペースのフォルダ | - |
| `--out` | 必須 | 書き出す HTML のファイルのパス。末尾は `.html`。ワークスペースの `preview.html` を指さない。親のフォルダは作らないので、先に用意する。相対パスは起動した場所から読む。既にあるファイルは置き換える | `~/渡す/新規事業の検討.html` |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `path` | str | 書き出した HTML の絶対パス |

書き出した HTML には、`build` の `preview.html` と同じ埋め込みのデータ（[プレビューを書き出す](#プレビューを書き出す)の表）に加えて、ライセンスの表示が入る。
ライセンスの表示は `<script type="text/plain" id="mindmap-licenses">` の中身で、画面には出ない。

| 内容 | 説明 |
| --- | --- |
| 中に持つライブラリ | marked・DOMPurify・elkjs・mermaid のそれぞれの名前・版・著作権の表示・ライセンスの名前と本文 |
| DOMPurify | Apache-2.0 を選んだ旨 |
| elkjs | EPL-2.0 を選んだ旨と、ソースコードの入手先（リポジトリと版のタグの URL） |
| mermaid | 配布ファイルが中に束ねた依存（d3・cytoscape・katex など）ごとの名前・版とライセンスの本文 |

### 終了コード

| コード | 意味 |
| --- | --- |
| `0` | 書き出せた |
| `1` | ワークスペースが無い・YAML がスキーマに合わないか YAML として読めない・jsDelivr から取れない（届かない・待ちの上限を超えた・取った配布ファイルが `integrity` と合わない）・書き込めなかった（`--out` の親のフォルダが無い）。前の `--out` のファイルを残す |
| `2` | 引数の誤り（`--out` の末尾が `.html` でない・ワークスペースの `preview.html` を指す）。何も書き込まない |

## ゴールに届いたかを読む

設定の `goal.phase` までのフェーズの検討事項が全て決着し、`goal.deliverables` の資料が全て完成しているかを判定し、届いたかと残りの項目を返す。
読むだけで、ファイルを書き換えない。

- 決着は、検討事項の状態が `決定済み`・`対象外`・`取り下げ` のどれか
- 判定に入れる検討事項は、`phases` の先頭から `goal.phase` までのフェーズのもの。それより後ろのフェーズと、`phases` に無いフェーズの項目は入れない
- 完成は、`goal.deliverables[].doc` が指す資料の状態が `完成` であること。`doc` を持たない納品物は残りに出る

### 使い方

```bash
python3 {スキルのフォルダ}/scripts/mindmap.py goal --workspace {フォルダ}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `--workspace` | 必須 | ワークスペースのフォルダ | - |

### 出力

届いていないときも判定そのものは正常に終えているので、同じ形の JSON を出し、終了コードは `0` にする。

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `reached` | bool | ゴールに届いたか。`remaining_decisions` と `remaining_deliverables` がどちらも空のときだけ `true` |
| `goal_phase` | str | 設定の `goal.phase` |
| `phases` | list[str] | 判定に入れたフェーズ（`phases` の先頭から `goal.phase` まで） |
| `remaining_decisions[]` | list[{id, title, phase, status}] | 判定に入れたフェーズの検討事項のうち、決着していないもの（フェーズの順、同じフェーズの中は連番の小さい順） |

## 記録の形式を移す

ワークスペースの版（`mindstella-version.ini`）とプラグインの版を比べ、間の版の手順（`skills/mindmap/migrations/{版}/steps.yaml`）を版の順に並べる・当てる。
値が要るキーを入れ、点検に合えば版のファイルを書き換える。

- `--plan`: 当てずに、版を比べた結果と当てる手順を返す。何も書き込まない
- 引数なし: 写しを取ってから、`--from` より後で `--to` 以下の版の手順を版の順に当てる。版のファイルは書かない。失敗したら写しから戻す
- `--set`: 値が要るキーに値を入れる
- `--record`: 全ての YAML をスキーマと突き合わせ、合えば版のファイルを書く

版は `v{メジャー}.{マイナー}.{パッチ}` で、`v` を落とした 3 つの整数を左から比べる。
版のファイルが無いワークスペースは、版を記録する前の形式として、どの版よりも古く扱う。
どの手順も、同じ手順を 2 度当てても結果が変わらない。
写しは、ワークスペースが git の作業ツリーの中にあり、ワークスペースの中に ignore されたファイルが 1 つも無いときだけ、ワークスペースのパスだけをコミットして取る。
そうでなければ、ワークスペースの隣の `{フォルダ名}.before-{--to の版}` へ複製する。
写しは成功しても消さない。

### 使い方

```bash
python3 {スキルのフォルダ}/scripts/mindmap.py migrate --workspace {フォルダ} --plan [--from {版}] [--to {版}]
python3 {スキルのフォルダ}/scripts/mindmap.py migrate --workspace {フォルダ} [--from {版}] [--to {版}]
python3 {スキルのフォルダ}/scripts/mindmap.py migrate --workspace {フォルダ} --set {ファイル}:{キーのパス}={値} [--set ...]
python3 {スキルのフォルダ}/scripts/mindmap.py migrate --workspace {フォルダ} --record [--to {版}]
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `--workspace` | 必須 | ワークスペースのフォルダ | - |
| `--plan` | 任意 | 当てずに、版を比べた結果と当てる手順を返す。`--set`・`--record` と一緒に使わない | - |
| `--from` | 任意 | この版より後の手順を当てる。省略すると、ワークスペースの版。版のファイルが無ければ、版を記録する前の形式 | `--from v0.2.0` |
| `--to` | 任意 | この版以下の手順を当てる。`--record` では書く版。省略すると、プラグインの版（`plugins/mindstella/version.ini` の 1 行目）。`--from` より前の版は渡さない | `--to v0.3.0` |
| `--set` | 任意 | 値が要るキーに入れる値。`{ファイル}:{キーのパス}={値}` を繰り返して渡す。`{ファイル}` はワークスペースからの相対パス、`{キーのパス}` は `.` 区切り。手順を当てる・`--record` と一緒に使わない | `--set mindmap.yaml:summary=要件出しのスキルを設計する` |
| `--record` | 任意 | ワークスペースを点検し、問題が無ければ `mindstella-version.ini` を `--to` の版に書き換える。`--plan`・`--set` と一緒に使わない | - |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `workspace_version` | str \| null | ワークスペースの版。版を記録する前の形式は `null` |
| `plugin_version` | str | プラグインの版 |
| `relation` | `older` \| `same` \| `newer` | プラグインの版と比べたワークスペースの版 |
| `steps[]` | list[{version, index, op, destructive, summary}] | 当てる（当てた）手順を版の順・並びの順に並べたもの。`--set`・`--record` では空 |
| `steps[].version` | str | 手順の版（`migrations/` のフォルダ名） |
| `steps[].index` | int | `steps.yaml` の中の 1 始まりの番号 |
| `steps[].op` | str | 操作（`rename_file`・`move_dir`・`delete`・`rename_key`・`set_default`・`map_values`・`call`） |
| `steps[].destructive` | bool | 破壊的な操作（`rename_file`・`move_dir`・`delete`）か |
| `steps[].summary` | str | 手順の中身の 1 行 |
| `needs_values[]` | list[{file, key, description}] | 手順を当てた後に値が要るキー。`--set` で値を入れるまで、点検に合わない。`--plan` でも返す |
| `backup` | {kind, ref} \| null | 取った写し。手順を当てたときだけ持つ |
| `backup.kind` | `git` \| `copy` | git のコミットか、フォルダの複製か |
| `backup.ref` | str | コミットの ID か、複製したフォルダの絶対パス |
| `recorded` | str \| null | `--record` で書いた版 |

### 終了コード

| コード | 意味 |
| --- | --- |
| `0` | 並べた・当てた・値を入れた・版を書いた、または当てる手順が無かった |
| `1` | ワークスペースが無い・手順を当てる、または `--record` で、ワークスペースの版がプラグインの版より新しい（標準エラーに 2 つの版と、プラグインを更新する旨。`--plan` は `relation: newer` を返して `0`）・手順が失敗した（写しから戻してから、標準エラーに `エラー: {版} の手順 {番号}（{操作}）: {理由}`）・`--record` で YAML がスキーマに合わない（合わない箇所を標準エラーに出し、版のファイルを書かない）・写しを取れない（手順を当てない）・書き込めなかった |
| `2` | 引数の誤り（版の形が違う・`--to` が `--from` より前・一緒に使わない引数を渡した・`--set` の形が違う） |
