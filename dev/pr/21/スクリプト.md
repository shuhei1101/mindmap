## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 雛形の組み立て | 画面の HTML・CSS・JavaScript を `skills/mindmap/preview/` に分けて持ち、`build` が CSS・JavaScript を HTML の中へ差し込んでから、データを埋め込んだ 1 枚を書き出す | 書き出す `preview.html` は今と同じく、ワークスペースの他のローカルのファイルを指さない |
| 埋め込みのデータ | 形を変えない（`settings`・7 種類・`bodies`・`built_at`） | 画面に要るデータが足りないと分かったときだけ、インターフェース定義設計で足す |
| 埋め込みの安全 | 差し込む CSS・JavaScript が `</style>`・`</script>` を含まないことを、書き出しの側で確かめる | 含むときは同梱の雛形の誤りとしてエラーにする |
| 資料の状態 | 資料の `done`（真偽値）を `status`（下書き / 確認中 / 完成）に置き換え、ゴール判定は成果物の資料が `完成` かで見る | 今の `done` を持つワークスペースは、コマンド `migrate` で一度だけ移す（`done: true` → `完成`、`done: false` → `下書き`。[確認ログ](./確認ログ.md)）。他のコマンドが `done` でスキーマに合わないときは `migrate` を案内する |
| 既存機能への影響 | `build` の引数・標準出力・終了コード・エラーは変えない | 既存の結合テストと E2E がそのまま通ること |
