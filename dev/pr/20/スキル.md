## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| スキルの分割 | セットアップ `setup` と話し合いを進めるスキルの 2 つを `skills/` の下にフォルダを分けて置く | 進めるスキルの名前はユーザーに確認する |
| 共通の置き場所 | `references/`・`playbooks/` と、既存の `schemas/`・`scripts/`・`preview/` を 2 つのスキルから読める場所に置く | 置き場所は PoC で確かめた参照の仕方で決める |
| SKILL.md | 入力・ステップの表・コマンドと引数の一覧だけを持ち、各ステップは `steps/` の手順を指す | ステップからはコマンド名で呼ぶ |
| steps/ | 要件の 7 ステップを 1 ステップ = 1 ファイルで書く。各手順の最後に `build` を流す | hooks は使わない |
| references/ | 質問の書式・文章の書き方・リサーチの調べ方（公式の資料 / 実践者の知見 / 技術の選定）を写して置く | 写し元の名前（AI Monitor）を出さない |
| playbooks/ | システム開発と調査の進め方ガイドを、フェーズの並び・観点・必ず調べるもの・ゴールの候補・引き渡しの形の同じ項目立てで書く | |
| README.md | はじめに・コアコンセプト・ユースケース（分野）・依存とインストール・使い方 | インストールは `claude plugin marketplace add shuhei1101/mindmap` と `claude plugin install mindmap@mindmap` |
| リサーチの確認 | サブエージェントの起動前に「何を・どの観点で・何体で」を出して確認を取る | 利用者が自分から頼んだときは省く |
| 外部ライブラリの設計書 | `claude-code.yaml` の一覧に、スキルの front matter・呼び名・同梱ファイルの参照・サブエージェントの起動を足す | #10 でユーザーが依頼 |
| アーキテクチャ図 | スキルのサブシステムを `implemented` にし、配置を分割後のフォルダに直す | |
| 既存機能への影響 | プラグインのマニフェストは変えない（`skills/` の下のフォルダを Claude Code が読む） | PoC で確かめる |
| 依存の確認（保守性） | セットアップは `check-env` の結果だけで止めるかを決め、Python の版の判定はスクリプトに任せる | |
| PoC で確かめる機構 | 1 つのプラグインの 2 つのスキルが `mindmap:setup` と `mindmap:{進めるスキル}` で呼べる / スキルが自分のフォルダの外の共通のファイルとスクリプトを参照できる / スキルの手順からサブエージェントを起動できる | 成り立たない機構は、置き場所かスキルの分け方を変えて確かめ直す |
