# 文章の書き方

文章を足す前に、既存の行を直す・消すことで足りないかを確かめ、足りるなら足さない。

検討事項の答え・資料の本文・リリースの資料・会話ログに文章を書いたら、書き終えた直後に次を確認して、当てはまる行を消す。
足した分は、読み手が読む量をそのまま増やす。

## 確認する項目

| 確認 | 当てはまったら消す理由 |
| --- | --- |
| 書いていない操作を禁じていないか | 書いていない操作は行われない |
| そう書く理由・背景・経緯を説明していないか | 読み手の判断が変わらないなら要らない |
| 同じ内容を別の項目・資料が持っていないか | 参照を 1 行残せば足りる |
| 直前の正の指示の裏返しになっていないか | 「〜する」の後の「〜しない」は情報量が無い |
| 本文にあることを、冒頭の文や概要で言い直していないか | 冒頭の文は 1〜2 行 |
| 冒頭の文・概要に後から情報を足していないか | 対象そのものが変わったときだけ書き換える |
| 後から増えうるものの個数を書いていないか | 増減のたびに数だけを直す差分が出る。数を消しても文は成立する |
| 1 つの説明が 3 行を超えていないか | 決めきれていないと言葉で埋めたくなる。内容を確定させれば短くなる |
| 消しても読み手の動きが変わらない行を残していないか | 変わらない行は、ほかの内容を埋もれさせる |
| 読み手が既に知っている一般の知識を説明していないか | 書くのは、この話し合いで決めたことだけ |
| 実装のコード例を載せていないか | 文で足りる。書式を示す例は、文より短く伝わるときだけ残す |
| 版・価格・閾値・モデル名など、時期で古くなる値を書いていないか | 古くなっても直されないまま残る。公式の参照先を書く |
| 選択肢を並べたまま、既定を決めていないか | 読み手が選べない。既定を 1 つ書き、例外だけ添える |
| 強調（必ず・絶対・重要・太字）を足していないか | 重ねると、どれも目立たなくなる |
| 推量やぼかし（〜と思われる・〜かもしれない）で書いていないか | 決めて書く |
| 冗長な言い回し（することができる・を行う）を使っていないか | 省いても意味が変わらない |
| 同じファイルの中で同じ説明を繰り返していないか（概要・まとめの節を含む） | 最も適切な 1 か所に置く |

残してよい否定は、実行しうる操作を止めるものだけ。

## 語の選び方

| 観点 | 書き方 |
| --- | --- |
| 呼び名を固定する | 同じものは同じ語で呼ぶ。決めた言い方は用語集に残し、別の言葉で言い換えない |
| 造語を作らない | 開発の現場で一般に使う語、または日本語にしたときの一般的な訳語で名付ける。比喩で名付けない |
| 定番の操作語を使う | 操作は 追加する・更新する・削除する・取得する・一覧する のような定番の動詞で書く |
| 値に軸の名前を添える | 値だけを書かず、何の値かを添える（`大` ではなく `影響度 大`） |
